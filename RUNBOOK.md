# avito-helper — что делать, когда сломалось

Короткий порядок действий на аварию. Подробности и история — в `CLAUDE-LOCAL.md`
и `CLAUDE-REFERENCE.md`. Составлено 14.10.2026 (К10 консилиума 29.09).

⚠️ Репозиторий **публичный** (проверено 14.10.2026). Токенов, ключей и
содержимого `.env` сюда не писать.

---

## 0. Где живут данные — сначала понять, что потеряно

Сырьё (История с финалами, эталоны, избранное) и промпт — невосполнимы.
Копий четыре, и ни одна не полная сама по себе:

| Копия | Что в ней | Чего в ней НЕТ |
|---|---|---|
| `localStorage` браузера | всё, включая корзину `avito_trash` и кладбище `avito_deleted` | второго устройства; стирается вместе с данными сайта |
| Файл «⬇ Бэкап JSON» (v3) | История, эталоны, избранное, пресеты, очередь, категории, сцены, каталоги, настройки, обложки | **корзины и кладбища**, токена |
| Сервер `~/avito-sync/voice.json`, `settings.json` + `history/` (5 версий) | сырьё и настройки, корзина в `voice` | то, что не успело уехать (синхронизация выключена или нет сети) |
| Журнал самообучения `~/avito-journal/*.jsonl` | событие `edited` несёт **обе версии текста** — бот и финал | записей без доноса финала; ретеншн 6 месяцев |

⚠️ Ловушка 14.09: пустая корзина в бэкапе **не значит**, что удалений не было —
корзины в бэкапе нет вовсе. Смотреть ⚙ Настройки → Синхронизация («в корзине: N»)
или серверный `voice`.

**Первое действие при любой подозрительной пропаже:** ничего не удалять и не
импортировать; сделать «⬇ Бэкап JSON» в текущем состоянии — это снимок для разбора.

## 1. Запись пропала из Истории / эталонов

1. ⚙ Настройки → Синхронизация → «🗑 Корзина — N, можно вернуть».
2. Нет в корзине — «⬆ Импорт» последнего бэкапа: **OK = слить** (добавит
   недостающее, существующее не тронет). «Отмена = заменить» — только если
   текущая база заведомо испорчена. Эталоны, избранное, пресеты и очередь
   при импорте всегда ДОБАВЛЯЮТСЯ.
3. Нет и там — на сервере: `~/avito-sync/history/` (предыдущие версии `voice`),
   затем журнал (`edited` → пара «бот → финал»). Это задача VPS-сессии
   **только на чтение**, образец — `TASK-HISTORY-RESCUE-VPS.md`. Так 13.09
   восстановлены Пермь и Саратов (`~/avito-rescue/finals.json`).

## 2. Плашка «изменения НЕ сохранены» / «обнови вкладку»

- **«НЕ сохранены»** — `localStorage` упёрся в квоту. Сразу «⬇ Бэкап JSON».
  Сырьё пишется первым, поэтому обычно теряется транзитное (результаты генерации),
  а не История. Освободить место: очистить результаты, пакет, лишние обложки.
- **«обнови вкладку»** — в соседней вкладке изменили сырьё или настройки.
  Обновить эту вкладку (F5), прежде чем что-то в ней менять: устаревшая вкладка
  затрёт настройки, категории, очередь и пресеты целиком.

## 3. На сайте старая версия

Сайт — GitHub Pages: https://enterteinment42.github.io/avito-helper/ ,
собирается с `main` за 1–3 минуты после пуша.

1. Проверить, что коммит запушен: `git log --branches --not --remotes --oneline` пуст.
2. **Ctrl+F5** (на телефоне — закрыть вкладку и открыть заново).
3. Свежесть — ⚙ Настройки → Профиль → «Версия файла» (дата изменения файла
   на сервере Pages), она же в подсказке на логотипе.

⚠️ Открывать только по этой ссылке. Файл с диска (`file://`) шлёт `Origin: null`,
прокси его не пропускает — «Failed to fetch» на любой генерации (Bug #10).

## 4. Испорчен `avito-helper.html`

Хук `.githooks/pre-commit` не даст закоммитить файл пустым, урезанным больше
чем на треть, без `</html>` в конце или удалённым. На новой машине подключить:

```
git config core.hooksPath .githooks
```

Откат до последнего коммита: `git restore avito-helper.html`.
Откат опубликованной версии — `git revert <коммит>` и пуш (не `reset` по
запушенному). ⚠️ Файл не писать через .NET/`Set-Content` из PowerShell:
25.09 так обнулили файл. Только редактором.

## 5. Генерация не работает — что значит ответ сервера

| Ответ | Значит | Что делать |
|---|---|---|
| Failed to fetch | CORS: открыт не с Pages-домена или сервер лежит | открыть по ссылке из п. 3; иначе — проверить сервер |
| 401 | неверный админ-токен (клиент его сбрасывает) | панель AI в форме генератора → «🔑 Сменить токен» |
| 404 | маршрута на сервере нет | сверить с репозиторием `poigraem-backend` (Bug #9: правка руками на сервере стирается `git pull`) |
| 413 | тело больше лимита (`/api/image` — 4 МБ) | меньше фото или меньше размер |
| 503 | на сервере не заведён ключ (`OPENROUTER_AVITO_KEY`) | VPS-сессия, `.env` |
| 504 | вендор не ответил вовремя | повторить |

Серверный код правится **только** в репозитории `poigraem-backend`;
копия `poigraem/backend/` не исполняется. Серверные шаги — через задание
VPS-сессии (`TASK-*-VPS.md`), журнал сервера — `CLAUDE-VPS.md`.

## 6. Перед тем как отдать правку

```
cd tests && npm install && npm test
```

Около 5 минут. Редкий таймаут Playwright на холодном старте — флак, повтор
проходит. Одна секция — `node run.mjs <имя>`. Любая правка, способная стереть
сырьё или промпт, закрывается тестом **до коммита**.
