# Авито-помощник (avito-helper)

Отдельное веб-приложение в рамках проекта «Поиграем» — полуавтоматизация размещения объявлений на Авито для продажи игр и подписок.

## Текущий фокус

**Этап:** Активная эксплуатация + начата реализация плана сближения с Айдентикой, направление 1 (категории-конструктор), этап 1 из 5. ⚠️ Рабочее дерево содержит незакоммиченную правку `avito-helper.html` (движок категорий, этап 1) — перед новыми правками файла проверить `git status`, чтобы не потерять её.
**Следующий шаг:** 🆕 Сессия 2026-09-06 (продолжение, направление 1) — начата реализация **направления 1 плана сближения с Айдентикой: категории-конструктор**. Денис подтвердил план «делать всё 3 направления (1, 2б, оценка 2а), но сейчас — 1» и выбрал полный объём: не одна категория «Физтовар», а конструктор — категории как данные, новые заводятся без правок кода. Работа разбита на 5 этапов, показаны Денису целиком: (1) движок дескрипторов, (2) редактор категорий в Настройках, (3) интеграция по всей карте (промпт распознавания/2а, инфографика, Сканер, few-shot, журнал), (4) сама категория «Физический товар» поверх движка, (5) сквозная проверка. **Этап 1 (движок) сделан, ещё НЕ закоммичен.** `CATS` стал массивом дескрипторов (поля, тип виджета, правило промпта, правило валидации) вместо 4 захардкоженных ярлыков; `catInfoBlock`/`validateForm`/`formHTML` собирают вывод из дескриптора циклом вместо `if/else` на 4 ветки; частные обработчики `plat`/`gplat`/`preorder` заменены общими `fchip`/`ftoggle` с ключом поля в `data-k`. Ключевое решение: значения полей остались ПЛОСКИМИ ключами `state.form` (не переехали во вложенную карту) — на них завязано ~40 мест (`currentProductName`, инфографика, IGDB, распознавание по фото, пресеты, снимок формы для ↻), так конструктор появился, а вылизанная генерация подписок не переписывалась. - **Нет потолка на размер одного события** — сосед подменяет заглушкой событие, в которое случайно попал base64 обложки (`CATALOG_EVENT_MAX`); у нас ограничение только общее `express.json({limit:'10mb'})`.
- **Уборка гоняется на каждом запросе** — у `/shop/journal` она троттлится раз в час; у нас `cleanOldJournal()` после каждого POST.
- **`slice(0, 500)` молча теряет хвост** — сервер режет батч, но отвечает `ok`, а клиент по `ok` удаляет весь отправленный батч. Сегодня не стреляет (клиент шлёт максимум 40), выстрелит при росте `J_BATCH_MAX`.
- **Повторы при частичной ошибке записи** — если запись упала между месячными файлами, клиент пришлёт батч заново; см. дедуп выше.

## Проблема

Продавец на Авито (лучший в регионе, 60+ объявлений подписок + 50-150 игр). Для конверсии нужно:
- Несколько объявлений одной подписки/игры в разных регионах

API Авито не даёт ключей, платная автоматизация неэффективна → нужен инструмент для **подготовки контента**, который потом копипастом вставляется на Авито.

### Поддерживаемые провайдеры

| Провайдер | Модели | Эндпоинт прокси | Статус |
|-----------|--------|-----------------|--------|
| Anthropic (Claude) | Sonnet 5 (по умолчанию), Opus 5, Haiku 4.5 | `/api/claude` | ✅ работает |
| OpenRouter | любые (зоопарк моделей) | `/api/openrouter` | ⚠️ эндпоинта нет на VPS, см. Bug #9 |

⚠️ **Модели различаются НАБОРОМ ПАРАМЕТРОВ ЗАПРОСА, а не только качеством** (сессия 2026-09-06). На моделях 5-го поколения и Opus 4.7+ параметр `temperature` **удалён и возвращает 400** — из-за этого «Opus 4.7» в списке ронял любую генерацию, пока никто его не выбирал. Поэтому в коде есть таблица `MODEL_CAPS` (`sampling` / режим размышления / версия инструмента веб-поиска) и `modelCaps(id)`; неизвестная модель получает самый осторожный набор — такой запрос примут и старые, и новые. **При добавлении модели в `CLAUDE_MODELS` обязательно добавлять строку в `MODEL_CAPS`**, иначе она молча поедет на осторожных дефолтах. Смена дефолтной модели требует и строки в `MODEL_MIGRATION` — иначе у Дениса в `localStorage` останется снятая модель, а селект покажет пустоту. Размышление (`thinking: {type:'adaptive'}`) просится точечно через `opts.thinking` — сейчас у распознавания по фото и поиска цены; оно тратится из `max_tokens`, поэтому лимиты там подняты.

Ключи хранятся в `.env` на VPS (не в браузере): `ANTHROPIC_KEY` (проверено), и, по аналогии с соседними ботами на том же VPS (`chat-bot`, `editorial-bot`), вероятно `OPENROUTER_API_KEY` — не `OPENROUTER_KEY`, как было записано здесь раньше (сессия 2026-09-06 нашла и поправила это по локальным копиям кода ботов, но сам `.env` на сервере в эту сессию не открывался). У соседних ботов этот ключ используется ТОЛЬКО для текста — вызов image-моделей с ним ещё не проверялся (нужен для направления 2б, см. «Текущий фокус»).

### Абстракция вызова (клиент)

```javascript
// Настройки провайдера хранятся в localStorage
const AI = {
  provider: 'claude',      // 'claude' | 'openrouter'
  model: 'claude-sonnet-4-20250514',
};

async function callAI(messages, system, opts = {}) {
  const provider = opts.provider || AI.provider;
  const model = opts.model || AI.model;

  if (provider === 'claude') {
    const res = await fetch('https://api.poigraem.shop/api/claude', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model,                    // claude-sonnet-4-... | claude-haiku-...
        max_tokens: opts.max_tokens || 4000,
        system,
        messages,                 // Anthropic-формат
      })
    });
    const data = await res.json();
    return data.content?.map(b => b.text).join('\n') || '';
  }

  if (provider === 'openrouter') {
    // OpenRouter = OpenAI-формат: system идёт первым сообщением
    const orMessages = system
      ? [{ role: 'system', content: system }, ...messages]
      : messages;
    const res = await fetch('https://api.poigraem.shop/api/openrouter', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model,                    // напр. 'anthropic/claude-3.5-sonnet', 'google/gemini-...', 'meta-llama/...'
        max_tokens: opts.max_tokens || 4000,
        messages: orMessages,
      })
    });
    const data = await res.json();
    return data.choices?.[0]?.message?.content || '';
  }
}
```

### UI переключения

- Селектор провайдера: Claude / OpenRouter
- Селектор модели (зависит от провайдера):
  - Claude: Sonnet (default), Haiku
  - OpenRouter: текстовое поле или список (можно вписать любую модель вручную)
- Настройка сохраняется в localStorage
- Можно задавать модель на уровне отдельной задачи (черновики — Haiku, финал — Sonnet)

**Важно:** форматы ответов разные — Claude отдаёт `content[].text`, OpenRouter `choices[0].message.content`. Абстракция `callAI()` это скрывает.

### 2026-08-13 — «Failed to fetch» диагностирован как поломка хостинга (Bug #10), инструмент вернулся на GitHub Pages
