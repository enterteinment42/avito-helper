🔴 **ТРИ МЕХАНИЗМА ПОТЕРИ ЗАПИСЕЙ ИСТОРИИ (найдены 14.09, исправлены).** Все три уносили записи МОЛЧА, мимо корзины:
1. **Близнецы по ключу-содержимому.** Личность записи считалась как `товар|регион|название|дата`, а повторные нажатия «✓ Размещено» создают записи с одинаковыми полями (дата — с точностью до дня). Удаление пустого дубля ставило надгробие на ОБЩИЙ ключ, и следующее слияние уносило по нему полноценную запись с финалом. Так пропали обе Сыктывкарские. **Лечение:** постоянный `_uid` каждой записи (миграция при запуске), ключ по содержимому стал ЗАПАСНЫМ и работает только там, где личности нет; снимок прежнего ключа хранится в `_ck0`, чтобы копия, уехавшая на сервер до миграции, опознавалась и не возвращалась двойником.
2. **Затирание из соседней вкладки.** `_saveAll` писал ключи целиком — побеждал тот, кто сохранил последним. Вкладка, пролежавшая 3 часа без дела, при первом же действии клала свой устаревший снимок и сносила всё, что завела соседняя. Так пропала Пермь: её создала вкладка B в 13:26, а вкладка A, открытая в 10:29 и ни разу не обновлявшаяся, перезаписала хранилище в 16:16. **Лечение:** сырьё (История, эталоны, избранное) пишется СЛИЯНИЕМ — `saveMerged()` читает хранилище и дописывает к своему набору чужое, с отсевом по кладбищу и перештамповкой совпавших id. Разбор идёт только когда строка отличается от записанной этой вкладкой, поэтому обычный `save` остался дешёвым.
3. **Удаление записи с финалом ничем не предупреждало** — вопрос был одинаковый для пустой строки и для пары «бот → правка». Теперь говорит прямо, с числом знаков.
➕ **ПРЕДОХРАНИТЕЛЬ НА СЫРЬЁ:** запись с непустым `finalDesc` не выбрасывается по надгробию-наследию (ключ по содержимому). Но явное удаление по ключу-личности уважается всегда — иначе строку нельзя было бы убрать вовсе.

🆕 **Задача следующей сессии — пул приёмов (посчитано 2026-09-11 по бэкапу, цифры проверяемые).** В пуле **125 уникальных приёмов** из 42 разобранных объявлений, в каждый запрос уходят 4 случайных. У пула ДВЕ независимые проблемы, и лечатся они по-разному:
1. **Клише — 10 бесспорных + 6 спорных.** Бесспорные (давят на эмоцию вместо товара): превосходная степень в заголовке, волшебное преображение, страх упустить (ограничение функционала без покупки), хайповая подводка перед списком, слоган-обещание образа жизни, призыв отказаться от скуки, броский слоган-афоризм, провокационное противопоставление «старое/новое», конструкция «не просто X, а Y», риторический вопрос про мечту покупателя. Спорные (обычное ремесло продающего текста, решать Денису): эмоциональный крючок в заголовке, глагол-приглашение, погружение в атмосферу, обещание новых впечатлений, обращение к «искателю впечатлений», экспертное определение категории. Лечится **механически**: группировать приёмы по смыслу и брать 4 из РАЗНЫХ тем, а не 4 случайных из 125. Ручной разметки не требует и, вероятно, даст больше, чем вычистка клише.

## AI-провайдеры и модели

Приложение поддерживает переключение между провайдерами и моделями. **Все запросы идут через прокси на VPS** — прямые вызовы из России блокируются (IP + DPI), прокси обходит это (как уже сделано для основного Поиграем).

### Поддерживаемые провайдеры

| Провайдер | Модели | Эндпоинт прокси | Статус |
|-----------|--------|-----------------|--------|
| Anthropic (Claude) | Sonnet 5 (по умолчанию), Opus 5, Haiku 4.5 | `/api/claude` | ✅ работает |
| OpenRouter | любые (зоопарк моделей) | `/api/openrouter` | ⚠️ эндпоинта нет на VPS, см. Bug #9 |

**Приоритет по умолчанию:** Claude Sonnet 5 (`claude-sonnet-5`). Haiku 4.5 — для дешёвых черновых генераций, Opus 5 — когда нужен максимум. OpenRouter — для экспериментов, но пока не работает.

⚠️ **Модели различаются НАБОРОМ ПАРАМЕТРОВ ЗАПРОСА, а не только качеством** (сессия 2026-09-06). На моделях 5-го поколения и Opus 4.7+ параметр `temperature` **удалён и возвращает 400** — из-за этого «Opus 4.7» в списке ронял любую генерацию, пока никто его не выбирал. Поэтому в коде есть таблица `MODEL_CAPS` (`sampling` / режим размышления / версия инструмента веб-поиска) и `modelCaps(id)`; неизвестная модель получает самый осторожный набор — такой запрос примут и старые, и новые. **При добавлении модели в `CLAUDE_MODELS` обязательно добавлять строку в `MODEL_CAPS`**, иначе она молча поедет на осторожных дефолтах. Смена дефолтной модели требует и строки в `MODEL_MIGRATION` — иначе у Дениса в `localStorage` останется снятая модель, а селект покажет пустоту. Размышление (`thinking: {type:'adaptive'}`) просится точечно через `opts.thinking` — сейчас у распознавания по фото и поиска цены; оно тратится из `max_tokens`, поэтому лимиты там подняты.

Ключи хранятся в `.env` на VPS (не в браузере): `ANTHROPIC_KEY` (проверено), и, по аналогии с соседними ботами на том же VPS (`chat-bot`, `editorial-bot`), вероятно `OPENROUTER_API_KEY` — не `OPENROUTER_KEY`, как было записано здесь раньше (сессия 2026-09-06 нашла и поправила это по локальным копиям кода ботов, но сам `.env` на сервере в эту сессию не открывался). У соседних ботов этот ключ используется ТОЛЬКО для текста — вызов image-моделей с ним ещё не проверялся (нужен для направления 2б, см. «Текущий фокус»).

### Абстракция вызова (клиент)

```javascript
// Настройки провайдера хранятся в localStorage
const AI = {
  provider: 'claude',      // 'claude' | 'openrouter'
  model: 'claude-sonnet-4-20250514',
};

async function callAI(messages, system, opts = {}) {
  const provider = opts.provider || AI.provider;
  const model = opts.model || AI.model;

  if (provider === 'claude') {
    const res = await fetch('https://api.poigraem.shop/api/claude', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model,                    // claude-sonnet-4-... | claude-haiku-...
        max_tokens: opts.max_tokens || 4000,
        system,
        messages,                 // Anthropic-формат
      })
    });
    const data = await res.json();
    return data.content?.map(b => b.text).join('\n') || '';
  }

  if (provider === 'openrouter') {
    // OpenRouter = OpenAI-формат: system идёт первым сообщением
    const orMessages = system
      ? [{ role: 'system', content: system }, ...messages]
      : messages;
    const res = await fetch('https://api.poigraem.shop/api/openrouter', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model,                    // напр. 'anthropic/claude-3.5-sonnet', 'google/gemini-...', 'meta-llama/...'
        max_tokens: opts.max_tokens || 4000,
        messages: orMessages,
      })
    });
    const data = await res.json();
    return data.choices?.[0]?.message?.content || '';
  }
}
```

### UI переключения

- Селектор провайдера: Claude / OpenRouter
- Селектор модели (зависит от провайдера):
  - Claude: Sonnet (default), Haiku
  - OpenRouter: текстовое поле или список (можно вписать любую модель вручную)
- Настройка сохраняется в localStorage
- Можно задавать модель на уровне отдельной задачи (черновики — Haiku, финал — Sonnet)

**Важно:** форматы ответов разные — Claude отдаёт `content[].text`, OpenRouter `choices[0].message.content`. Абстракция `callAI()` это скрывает.

## Правила и ограничения Авито

### Лимиты
- **Название:** строго до 50 символов с пробелами
- **Описание:** лимит очень большой — для наших объявлений не актуален
- **Фото:** до 10 штук на объявление; предпочтительно вертикальные

### Запрещено (снимают объявление)
- Ссылки на внешние ресурсы, QR-коды
- Упоминание других каналов связи («пишите в Telegram», «WhatsApp» и т.п.)
- Любые намёки на продажу аккаунта — писать нельзя ни в каком виде

### Обязательные фразы
- **Для игр:** «оформляется в цифре» — обязательно
- **Для игр и подписок:** указывать платформы (PS4/PS5, Xbox и т.п.) — и в названии, и в описании

### CTA (разрешённые)
- Отсылка в личку Авито — не банят: «Не нашли нужную игру? Пишите в личку — у нас большой каталог»
- Мягкий апсейл в конце объявления: упоминание что есть другие игры и подписки

### Как Авито определяет дубли
По фото, по названию и по тексту описания. Одинаковые фразы (особенно длинный список игр) — прямой путь к бану. Поэтому:
- Разные объявления = разные точки в пространстве вариаций
- В одном регионе не размещать слишком похожие объявления

### Оси рандомизации (примеры реальных замен)
**Названия игр** — одно и то же можно написать по-разному:
- `Red Dead Redemption 2` / `RDR 2` / `рдр2` / `rdr2`
- `FC 26` / `FC26` / `FIFA 26` / `ФИФА 26` / `фифа26`
- `UFC 5` / `ЮФС 5` / `юфс5`

**Названия подписок** — варьировать в названии И в теле:
- `PS+ Extra` / `ПС+ Экстра` / `PS Plus Extra` / `ПС Плюс Экстра` / `подписка пс плюс`

**Платформы** — тоже разные форматы:
- `PS4/PS5` / `ПС4,ПС5` / `пс4 пс5` / `для пс4 пс5` / `подписка на пс4,пс5`

**Список игр** — базовый скелет + ротация:
- Не менять весь список, но менять порядок, набор «дополнительных» игр, стиль оформления (запятые / с новой строки / через dash)

### SEO: по каким запросам ищут
Люди ищут игры разными способами:
- На русском: «человек паук», «гта 5», «ведьмак», «призрак цусимы»
- Транслит: «spiderman пс5», «gta5 пс4», «witcher 3»
- Аббревиатуры: «rdr2», «rdr 2», «гта», «мк11»
- С платформой: «игры пс5», «подписка пс плюс», «game pass xbox»
- С ценой: «купить ps plus дёшево», «ps plus 12 месяцев»

Генератор должен учитывать эти варианты при формировании описания.

### 2026-09-22 — Ротация объявлений, учёт по аккаунтам, сцены интерьера как данные; 2б подтверждено живьём

**Контекст:** сессия началась с вопроса «выполнен ли план сближения с Айдентикой» и переросла в стратегическую аналитику масштабирования, а затем в две крупные правки. По ходу **Денис подтвердил, что прогнал фото консолей в интерьере — работает**, чем закрыл последнее непроверенное звено направления 2б (у всех прежних проб был `refs=0`).

**Аналитика масштабирования (по прямому запросу).** Разобрано: что у Айдентики лучше, чего нет у обоих, как масштабировать на чужие ниши и как собирать сырьё клиентов. Ключевые выводы: визуал перестал быть преимуществом (Айдентика, Fabula.ai, MPCard.AI — инфографика за 200-800 ₽ у любого), мы в другой категории — поток объявлений против витринной карточки; у Авито нет открытого API объявлений, официальный путь — XML-фид автозагрузки, и клиент, который им уже пользуется, отдаёт весь свой корпус одним импортом; ниши делятся надвое — товарам нужен антидубль, услугам (ноготочки) он не нужен вовсе, им нужны скорость ответа и отзывы, то есть одним продуктом эти аудитории не закрываются.

**Что решил Денис по итогам аналитики:**
- Фичи «быстрый ответ в переписке» и «петля на просмотрах/контактах» — **отклонены**. Про переписку прямо: «я вполне в состоянии сам ответить клиенту… копировать вопрос и вставлять обратно — бредятина».
- **Экспортная версия для клиентов — ОТДЕЛЬНОЕ приложение**, а не сборка из одного исходника. Я предупредил про дрейф двух копий (прецедент Bug #9, два репозитория бэкенда) и предложил сборщик; Денис после объяснения подтвердил решение — форк.
- Свои товары: **техника и гейминг, хобби (без книг), гаджеты, музыкальные инструменты**; одежда и обувь — для экспортной версии.
- Антидубль по сценам отклонён: «я просто сгенерирую новое фото в новой сцене, к чему мне эта опция, только токены жечь».
- Из способов сбора сырья выбрана **голосовая анкета** (оказалась бесплатной: Claude аудио на вход не принимает, но браузерное распознавание речи и диктовка на телефоне дают транскрипт даром).
- ⚠️ **Поправка Дениса, которую принял:** копировать чужие объявления в эталоны можно — запрет на дубли работает внутри своего аккаунта, а чужой текст правилами не ограничен. Моя оговорка касалась только массового автосбора ботом.

**Правка 1 — ротация и аккаунты (`0c84420`).** Объявление выдыхается, и Денис крутит его руками: тот же текст с другими формами написания и новым заголовком. Сделано: **две степени** — 🔁 лёгкая (прокрутка, ~треть слов, структура и факты неприкосновенны) и ↺ средняя (существующий перефраз); крутится **донесённый финал**, а не бот-версия; в промпт уходит список **занятых названий** по товару и аккаунту; «✓ Разместил» заводит новую запись со ссылкой `_rotFrom`, прежнюю переводит в «Снято» и её сырьё не трогает. Порог 14 дней в настройках, свой срок и «не ротировать» у записи, правка даты публикации, сводка «пора обновить» и фильтр. **Аккаунты** — список в настройках (не два зашитых), метка у записи, колонка и фильтр; ручная запись в Истории приняла текст объявления и галочку «заодно в эталоны». Это закрыло дыру: половина работы Дениса (второй аккаунт, объявления без генератора) была вне учёта вовсе.

**Правка 2 — сцены интерьера (`142f356`).** По вопросу Дениса «стоит ли добавить сцен, товары-то разные». Выяснил и сообщил факт: **категория товара в промпт сцены не передаётся**, поэтому привязка сцен к категориям дала бы только удобство выбора — Денис на этом основании выбрал общий список. Сцен стало **18** в четырёх группах, компоновка «частые сверху + Ещё сцены», редактор в ⚙ Настройках (заводские правятся патчем-отличием, как категории). По прямому требованию Дениса добавлены **блоки достоверности**: комнатные сцены просят обычное телефонное фото с бытовыми мелочами, студийные — честную предметную съёмку, обе запрещают рендер, CGI, рекламный глянец и требуют общего освещения товара и фона (иначе предмет читается вклеенным). Это та же отстройка от нейротекстов, только для фото.

**Два круга код-ревью, 16 находок, все исправлены до коммитов.** Тексты — в `AUDITS-ARCHIVE.md`. Самая важная повторяла дефект, закрытый 11.09: список «частых сцен» я положил в `state.settings`, а по отличию настроек от заводских синхронизация решает, можно ли отправить документ на сервер — то есть после первой же генерации картинки пустой телефон затёр бы категории и пресеты, накопленные на ПК. Вторая по весу: аккаунт не расходился между устройствами, потому что миграция проставляет его всем записям до первого pull, и ветка переноса была мертва.

**Новые баги:** не найдено вне собственного кода сессии.

### 2026-09-14 — Пропали финалы: три механизма потери, сырьё восстановлено полностью

**Контекст:** сессия началась с жалобы Дениса — «после обновления пропали финалы, отображается 2, хотя должно быть 4 или 5». Это прямая угроза главной ценности проекта, поэтому всё остальное отложено.

**Итог: потерь нет ни одной.** Финалов было ровно 5, восстановлены все 5.

**Как разбирались (и чем ошибался я):**
- Первая гипотеза — близнецы по контент-ключу — оказалась верной, но я отбросил её на середине: в обоих файлах-бэкапах `trash: 0` и `deleted: 0`, и я прочитал это как «удалений не было». **На самом деле корзина и кладбище просто не входят в экспорт**, а мой скрипт показал отсутствующие поля нулями. Развернуло обратно только сообщение Дениса со статусом синхронизации: «в корзине: 3».
- Вторая ошибка была ценной по-другому: Денис поправил, что в корзине лежат **осознанно удалённые дубли-пустышки**, а пропало нужное. Это и вывело на настоящий механизм — надгробие на общем ключе.
- Вклад VPS-сессии оказался решающим: она нашла каталог `history/`, которого не было в моей задаче, и в нём — версию хранилища от 12.09 14:30 с двумя живыми финалами. Плюс доказала журналом, что вкладки работали внахлёст.

**Три механизма (все уносили записи молча, мимо корзины):**
1. **Близнецы.** Повторные нажатия «✓ Размещено» дают записи с одинаковыми товаром, регионом, названием и датой — то есть с ОДНИМ ключом. Удаление пустого дубля ставило надгробие на общий ключ, слияние уносило по нему запись с финалом. Обе Сыктывкарские.
2. **Затирание из соседней вкладки.** Вкладка A открыта в 10:29 и 5 часов молчала; Пермь создала вкладка B в 13:26; в 16:16 A ожила, разместила своё объявление и записала хранилище снимком трёхчасовой давности. Доказано по `build` (`document.lastModified`) в событиях `app_start`: два разных значения чередуются во времени.
3. **Удаление записи с финалом ничем не предупреждало.**

**Что сделано в коде (`8288376`, стенд 857/857, +32 проверки):** постоянный `_uid` всем записям с миграцией при запуске; разделение ключей на личность и запасной (`SYNC_KIND`, `syncMatcher`); запись сырья слиянием (`saveMerged`) вместо перезаписи; предохранитель `syncKilled` — финал не выбрасывается по надгробию-наследию, но явное удаление уважается; предупреждение при удалении записи с финалом.

**Что решили (развилки, `AskUserQuestion` + диалог):**
- Сохранность: полный экспорт сейчас → серверное хранение следующим шагом.
- Отбор: гибрид (близкий + жребий), полный текст без урезания, блок заголовков и в обычной генерации тоже.
- Мера близости: вес по редкости слова + запрос из всех полей формы (словарь классов товара отклонён как требующий ручного ведения).
- Слот голоса: схема «3 + 2» (идея Дениса), слот A по категориям поровну, слот B по всему корпусу.
- Финалы: гарантированный слот от двух штук.
- Синхронизация: два документа с разными правилами; удаление расходится на все устройства, но с корзиной.
