⚠️ **6 ОТКРЫТЫХ находок код-ревью (high effort, полный 8-угловой прогон) + ручной проход — НЕ применены, решение отложено. Все анкеры — `avito-helper.html`:**
1. 🔴 **`3296` — незаэкранированный `src` картинки.** `st.img.dataUrl` вставляется в `<img src="…">` без `esc()`, а он несёт вендорские данные: `media_type` на пути `b64_json` (достижимо даже на «правильном» ответе) или голый `url` на fallback-ветках. `media_type` вида `image/png"><img onerror=…>` — инъекция HTML/JS. (Ловил и ручной проход.)
2. 🔴 **`3262` — удалённый URL результата портит канвас обложки.** Если `stagedExtractImage` вернул cross-origin http(s)-URL (одна из поддержанных форм), `stagedToCovers` грузит его в `cv.images`; последующий `cvDownload`→`toDataURL()` бросит SecurityError (tainted canvas), скачивание обложки молча падает. Путь `b64_json`/data-URL безопасен, ломает только `url`-форма.
3. 🔴 **`3231` — журнальная атрибуция расходится с промптом.** `category`/`product` в событии `staged` читаются на завершении запроса, а не захвачены до `await`; форма (в отличие от чипов сцены) во время генерации (до 280с) не заблокирована → сменил категорию → в журнал уедет не та, по которой строился промпт. `scene` захвачен верно, эти два — нет. (Ловил и ручной проход.)
4. 🟠 **`3182` — altitude, корень №1 и №2.** `stagedExtractImage` может вернуть удалённый URL, а все потребители (img src, `el.src` для обложек, `a.href` для скачивания) ждут локальный `data:`-URL; экранировать у одного потребителя — заплатка. Глубокий фикс: нормализовать в `data:`-URL на границе (fetch remote→blob→dataURL) или пока НЕ принимать `url`-формы (документированная форма ответа OpenRouter — `data[].b64_json`), тогда №1 и №2 закрываются в корне.
5. 🟡 **`3248` — `stagedToCovers` дублирует `visionToCovers`** почти дословно (game-confirm, лимит 10, `new Image`→push+jlog+tab+render, onerror-toast); различие — текст, `source` в jlog и какой dataUrl. Свести в общий хелпер `pushImageToCovers(dataUrl, {source, extra})`.
6. 🟡 **`3229` — событие `staged` без `phase` у генерации** (у скачивания `phase:'download'`), разделять «сгенерировано/скачано» придётся по отсутствию поля — хрупко, у соседнего `vision` фаза всегда есть. Добавить `phase:'generate'`; плюс `staged` ещё не внесён в таксономию `tools/journal-report.mjs` (как в своё время `vision`). (Третья находка ручного прохода.)
**Рекомендация к следующей сессии:** №1+№4 закрывают и №2 в корне (нормализация результата в `data:`-URL); №3 дёшев и это сквозная ценность (честность журнала). №5/№6 — по желанию. Живьём клиент проверять только после того, как сервер получит ключ и `/api/image` перестанет отвечать 503.

## AI-провайдеры и модели

Приложение поддерживает переключение между провайдерами и моделями. **Все запросы идут через прокси на VPS** — прямые вызовы из России блокируются (IP + DPI), прокси обходит это (как уже сделано для основного Поиграем).

### Поддерживаемые провайдеры

| Провайдер | Модели | Эндпоинт прокси | Статус |
|-----------|--------|-----------------|--------|
| Anthropic (Claude) | Sonnet 5 (по умолчанию), Opus 5, Haiku 4.5 | `/api/claude` | ✅ работает |
| OpenRouter | любые (зоопарк моделей) | `/api/openrouter` | ⚠️ эндпоинта нет на VPS, см. Bug #9 |

**Приоритет по умолчанию:** Claude Sonnet 5 (`claude-sonnet-5`). Haiku 4.5 — для дешёвых черновых генераций, Opus 5 — когда нужен максимум. OpenRouter — для экспериментов, но пока не работает.

⚠️ **Модели различаются НАБОРОМ ПАРАМЕТРОВ ЗАПРОСА, а не только качеством** (сессия 2026-09-06). На моделях 5-го поколения и Opus 4.7+ параметр `temperature` **удалён и возвращает 400** — из-за этого «Opus 4.7» в списке ронял любую генерацию, пока никто его не выбирал. Поэтому в коде есть таблица `MODEL_CAPS` (`sampling` / режим размышления / версия инструмента веб-поиска) и `modelCaps(id)`; неизвестная модель получает самый осторожный набор — такой запрос примут и старые, и новые. **При добавлении модели в `CLAUDE_MODELS` обязательно добавлять строку в `MODEL_CAPS`**, иначе она молча поедет на осторожных дефолтах. Смена дефолтной модели требует и строки в `MODEL_MIGRATION` — иначе у Дениса в `localStorage` останется снятая модель, а селект покажет пустоту. Размышление (`thinking: {type:'adaptive'}`) просится точечно через `opts.thinking` — сейчас у распознавания по фото и поиска цены; оно тратится из `max_tokens`, поэтому лимиты там подняты.

Ключи хранятся в `.env` на VPS (не в браузере): `ANTHROPIC_KEY` (проверено), и, по аналогии с соседними ботами на том же VPS (`chat-bot`, `editorial-bot`), вероятно `OPENROUTER_API_KEY` — не `OPENROUTER_KEY`, как было записано здесь раньше (сессия 2026-09-06 нашла и поправила это по локальным копиям кода ботов, но сам `.env` на сервере в эту сессию не открывался). У соседних ботов этот ключ используется ТОЛЬКО для текста — вызов image-моделей с ним ещё не проверялся (нужен для направления 2б, см. «Текущий фокус»).

### Абстракция вызова (клиент)

```javascript
// Настройки провайдера хранятся в localStorage
const AI = {
  provider: 'claude',      // 'claude' | 'openrouter'
  model: 'claude-sonnet-4-20250514',
};

async function callAI(messages, system, opts = {}) {
  const provider = opts.provider || AI.provider;
  const model = opts.model || AI.model;

  if (provider === 'claude') {
    const res = await fetch('https://api.poigraem.shop/api/claude', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model,                    // claude-sonnet-4-... | claude-haiku-...
        max_tokens: opts.max_tokens || 4000,
        system,
        messages,                 // Anthropic-формат
      })
    });
    const data = await res.json();
    return data.content?.map(b => b.text).join('\n') || '';
  }

  if (provider === 'openrouter') {
    // OpenRouter = OpenAI-формат: system идёт первым сообщением
    const orMessages = system
      ? [{ role: 'system', content: system }, ...messages]
      : messages;
    const res = await fetch('https://api.poigraem.shop/api/openrouter', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model,                    // напр. 'anthropic/claude-3.5-sonnet', 'google/gemini-...', 'meta-llama/...'
        max_tokens: opts.max_tokens || 4000,
        messages: orMessages,
      })
    });
    const data = await res.json();
    return data.choices?.[0]?.message?.content || '';
  }
}
```

### UI переключения

- Селектор провайдера: Claude / OpenRouter
- Селектор модели (зависит от провайдера):
  - Claude: Sonnet (default), Haiku
  - OpenRouter: текстовое поле или список (можно вписать любую модель вручную)
- Настройка сохраняется в localStorage
- Можно задавать модель на уровне отдельной задачи (черновики — Haiku, финал — Sonnet)

**Важно:** форматы ответов разные — Claude отдаёт `content[].text`, OpenRouter `choices[0].message.content`. Абстракция `callAI()` это скрывает.

## Правила и ограничения Авито

### Лимиты
- **Название:** строго до 50 символов с пробелами
- **Описание:** лимит очень большой — для наших объявлений не актуален
- **Фото:** до 10 штук на объявление; предпочтительно вертикальные

### Запрещено (снимают объявление)
- Ссылки на внешние ресурсы, QR-коды
- Упоминание других каналов связи («пишите в Telegram», «WhatsApp» и т.п.)
- Любые намёки на продажу аккаунта — писать нельзя ни в каком виде

### Обязательные фразы
- **Для игр:** «оформляется в цифре» — обязательно
- **Для игр и подписок:** указывать платформы (PS4/PS5, Xbox и т.п.) — и в названии, и в описании

### CTA (разрешённые)
- Отсылка в личку Авито — не банят: «Не нашли нужную игру? Пишите в личку — у нас большой каталог»
- Мягкий апсейл в конце объявления: упоминание что есть другие игры и подписки

### Как Авито определяет дубли
По фото, по названию и по тексту описания. Одинаковые фразы (особенно длинный список игр) — прямой путь к бану. Поэтому:

- **Карточка «📷 Распознать по фото»** в форме генератора (коммит `9289065`). Фото → категория и поля формы; для физтовара (консоль, геймпад, диск в коробке) — название плюс состояние и комплектация **ровно по фото**: промпт отдельно запрещает додумывать объём памяти, ревизию и комплект, которых не видно, и требует `confidence: low` с объяснением, если разобрать нельзя. Рядом — «💰 Узнать рыночную цену» (веб-поиск, отдельной кнопкой, чтобы не жечь платный поиск на каждом фото), «🖼 → в обложки» (фото товара чаще всего и есть будущая обложка) и «↩ Вернуть форму».
- **Правок на VPS не потребовалось** — в отличие от направления 2б. Проверено по коду прокси: `/api/claude` пересылает тело как есть (`server.js:952`), лимит 10 МБ; фото ужимается в браузере до 1568px/JPEG (рекомендация Anthropic), телефонный снимок на 12 МБ превращается в ~150 КБ base64.
- **`callAI` получил `opts.system`** — у распознавания свой промпт, общий SYS с правилами объявлений там мешает.
- **Апгрейд моделей** (коммит `1042b9a`): список был на поколение позади. Стало **Sonnet 5 (дефолт), Opus 5, Haiku 4.5**; Sonnet 5 не только новее прежнего дефолта Sonnet 4.6, но и **дешевле** ($2/$10 против $3/$15 за 1М токенов). Введена таблица `MODEL_CAPS` (sampling / режим размышления / версия веб-поиска) вместо одного набора параметров на всех, плюс перенос сохранённых настроек со снятых моделей. Распознавание и поиск цены получили **adaptive thinking** (там нужен разбор, а не первое впечатление) и поднятые лимиты — размышление тратится из того же `max_tokens`.
- **Правки по двум кругам код-ревью** (коммит `29cb7fe`) — см. «Новые баги» ниже.

**Проверка:** 93/93 headless (Playwright, реальные функции приложения; стабы только на границах `callAI`/`confirm`), консоль чистая. Реальное ужатие холста 3000×2000, настоящий `input[type=file]`, состав того, что уходит в API (image-блок base64, свой system, провайдер, наличие/отсутствие `temperature` и `thinking` по каждой модели), фильтрация выдумок модели, обе ошибки с восстановлением, клики настоящей мышью, `page.reload()`, все три пути импорта Истории, регресс генерации и всех 6 вкладок. **Живая приёмка Денисом состоялась:** распознавание отработало на боевой ссылке с настоящим токеном — это подтверждает заодно и доступность Sonnet 5 по ключу, и то, что связка Pages → прокси → Claude работает end-to-end.

**Что решили (развилки, `AskUserQuestion`):**
- Место фичи — карточка прямо в форме генератора (не отдельная вкладка, не конструктор обложек): «сфоткал → поля заполнены → генерировать» без переключений.
- Объём — поля формы, а **цена отдельной кнопкой**: платный веб-поиск не должен уходить на каждое фото, а цифра не должна подставляться молча.
- Фото после распознавания — по кнопке «→ в обложки», не автоматически: автоперенос затирал бы картинку в режиме «Игра» и молча занимал слот в коллаже.
- Модели — полный апгрейд (а не «только починить Opus» и не «новая модель только для vision»).

**Новые баги (найдены код-ревью, все исправлены в этой же сессии, коммит `29cb7fe`):**
- **Запрос цены уходил с промптом РАСПОЗНАВАНИЯ** — а тот требует другую JSON-схему и прямым текстом велит «Цену НЕ придумывай». Модель имела полное право вернуть не тот ответ, и оплаченный веб-поиск сгорал впустую. Самая дорогая из находок; headless-тесты её не ловили, потому что стаб отвечал правильным JSON независимо от промпта — **урок: стаб, всегда возвращающий «правильный» ответ, не проверяет промпт**.
- **Гонка при смене фото** — выбрал фото Б, пока распознаётся А: результат по А ложился в форму, а карточка показывала Б. Теперь на время запроса выбор фото и «убрать» заблокированы.
- **Категория не из списка молча роняла все поля** (модель отвечает `"Игра"` вместо `"game"`) — форма падала в «Цифровой товар» пустой, а карточка рапортовала «поля заполнены», и генерация уходила по пустой форме, сжигая токены. Теперь считаются реально заполненные поля, при нуле — предупреждение.
- Плюс четыре мелких: снимок формы для отката перетирался вторым распознаванием подряд; после отката карточка продолжала утверждать «поля заполнены»; «убрать фото» во время поиска цены выбрасывало оплаченный результат; «Рынок: 1200– ₽» при неполном ответе.
- **`temperature` на моделях 5-го поколения и Opus 4.7+ возвращает 400**, а `callAI` слал её всегда → выбор «Opus 4.7» в настройках AI **гарантированно ронял любую генерацию**. Не всплывало только потому, что дефолтом был Sonnet 4.6, где она ещё разрешена. Закрыто таблицей `MODEL_CAPS`.
- **Импорт Истории (код второй сессии)** — слияние эталонов выполнялось ДО второго `confirm`, а отказ от замены базы делал `return` без `save()`/`renderDb()`: эталоны из файла оседали в памяти невидимо и уезжали на диск при первом постороннем `save()`. Исправлено с разрешения Дениса после того, как та сессия завершилась; её сознательное правило «эталоны сливаются даже при выборе „заменить“» сохранено.

**Открытые вопросы:**
- Качество распознавания Денис оценил как «так себе» ДО апгрейда моделей. После перехода на Sonnet 5 + adaptive thinking повторной оценки ещё не было.
- Судьба тест-драйвера (теперь 93 проверки) — по-прежнему в смертной scratchpad-директории.
