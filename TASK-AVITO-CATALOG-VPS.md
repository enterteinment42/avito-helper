# Сервер единого каталога avito-helper

Клиентская задача — [TASK-AVITO-FOUR-WINDOWS.md](TASK-AVITO-FOUR-WINDOWS.md), пункт 4. Денис редактирует каталог из «Настроек» помощника. Клиент использует действующую авторизацию синхронизации.

## Контракт

- `GET /api/avito-sync/catalog` возвращает `{data:{products:{}},updated:null}` для пустого каталога. Для существующего документа `updated` — та же непрозрачная версия, что у `voice`, и `data.products` — объект товаров.
- `POST /api/avito-sync/catalog` принимает `{base,data:{products},device}`. `base` обязателен, включая явный `null` при создании. Хранить каталог отдельно от `settings` и `voice`. Сравнение версии и запись должны быть атомарными. При несовпадении — `409`, при успехе — `{updated: <новая версия>}`.
- Ключ товара — отображаемое имя из текущих списков помощника. Значение — `{prices, games}` для PS Plus либо `{prices, features}` для AI-подписок. `prices` — объект: срок «1 месяц», «3 месяца», «6 месяцев» или «12 месяцев» → положительное целое число рублей. Пустое значение хранится отсутствующим ключом. `games` и `features` — строки, пустая строка допустима.
- Проверить типы, размер запроса и атомарность записи. Хранить предыдущую версию по схеме действующей синхронизации. Начальный каталог пустой до заполнения Денисом.

## Приёмка

1. Без авторизации запрос отклоняется. Старые клиенты с `voice` и `settings` работают как прежде.
2. Два клиента получают одну версию, первый сохраняет, второй получает 409 с устаревшим `base`. После свежего GET второй применяет только своё изменение. Первый товар остаётся в каталоге.
3. Каталог переживает перезапуск сервиса. Пустые поля не превращаются в нули. Старый бэкап настроек не затрагивает каталог.
4. После выкладки проверить браузером сохранение на одном устройстве и подстановку на другом. Черновик, открытый на втором устройстве до обновления, сохраняет свой ввод.
