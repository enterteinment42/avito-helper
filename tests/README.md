# Регрессионный стенд avito-helper

Гоняет **настоящие функции приложения** в headless-браузере (Playwright + Chromium).
Заглушки ставятся только на границы: `callAI`, `fetch`, `confirm`, `prompt`, `Math.random`.

## Запуск

```bash
cd tests
npm install                    # один раз
npx playwright install chromium  # если браузера ещё нет в кэше
npm test
```

Выход: список проверок и итог `N/N`. Ненулевой exit code = что-то упало.

## Что внутри

| Секция | Что проверяет |
|---|---|
| `parity` | Промпт (`catInfoBlock` / `buildMsg`), `validateForm`, системный промпт (`buildSys`) и вердикты Сканера (`checkAds`) сравниваются **байт-в-байт** с версией из `git HEAD`. Главная страховка рефакторинга: генерация подписок вылизана десятком сессий, менять её молча нельзя. |
| `editor` | Конструктор категорий: создание, поля, порядок, скрытие, обязательность, сброс к заводской, экспорт/импорт JSON, персист через `reload()`. |
| `stage3` | Категория правит Сканер и SYS одними галочками, штамп товара по флажку «название», инфографика и распознавание по фото собираются из дескрипторов. |
| `phys` | Встроенная категория «Физический товар» целиком: форма, промпт, свои правила Сканера, SYS, инфографика, распознавание, генерация, правка патчем и сброс. |
| `fewshot` | Образцы языка в промпте: избранное + свои эталоны (✍), приоритет своей категории, переток из чужой с пометкой, крючки заголовков физтовара, разбор чужих эталонов (👀) на приёмы и подмешивание приёмов вместо текста. |
| `uncertain` | Уточняющие чипы распознавания: узкий порог (единственный вариант, неизвестное поле, значение вне списка опций и мусор отсеиваются), выбор человека, журнальные пары «предложено → выбрано», сброс при откате формы. |
| `review` | Находки код-ревью этапов 2–4, закреплённые тестом: тумблер не шлёт `false` в промпт, название категории экранируется, очистка полей встроенной категории применяется, инфографика не рисует запрещённую цену, устаревшее значение `select` не уходит в промпт. |
| `journal` | Доставка событий журнала: ключ идемпотентности `eid`, пауза после неудач (назначается, растёт, не пропускает повторных запросов, снимается успехом), отвергнутый батч выбрасывается без роста паузы, без токена запрос не уходит, перепись кликов отсекает занятые кнопки по флагу каждого действия, вкладки рендерятся при недоступном `localStorage`. |
| `staged` | «Товар в интерьере» (2б): промпт запрещает перерисовывать товар и добавлять комплектацию, тело запроса собирается белым списком (модель и `n` клиент не задаёт, соотношение 3:4), терпимый разбор ответа вендора по всем правдоподобным формам с внятной ошибкой при промахе, `503` (нет ключа на сервере) НЕ сбрасывает админ-токен, а `401` сбрасывает, смена фото убирает интерьер прежнего товара, `freshVision()` не роняет карточку после «убрать фото», ничего не попадает в `localStorage`. |
| `backup` | Полный бэкап (v3): в файл идёт всё накопленное руками (история, эталоны, избранное, пресеты, очередь, категории, каталоги, настройки, обложки), админ-токен и транзитные результаты генерации — нет; импорт на чистом браузере восстанавливает это и переживает F5, повторный импорт не двоит (дедуп по содержимому, не по id), коллизии id разводятся и ссылка очереди на избранное чинится, отказ от настроек оставляет свои, отмена замены не добавляет ничего, старые форматы файла (голый массив и `{db, refs}`) по-прежнему принимаются, мусорный файл даёт понятную ошибку. |
| `sync` | Синхронизация с сервером плюс 10 находок её код-ревью: объединённый набор уезжает обратно (иначе записи остаются на одном устройстве), финал догоняет уже известную запись Истории, повторно заведённая запись снимает метку удаления, переключение голоса не плодит копий, пустой браузер не стирает настройки на сервере, кнопка отправки не врёт про успех, возврат из корзины, подпись ловит правку той же длины, правка во время отправки не теряется, корзина ограничена байтами. Плюс: подпись документа отсекает лишние отправки, пустой клиент НЕ стирает сырьё на сервере, слияние не двоит и доезжает до диска, удалённое не возвращается с сервера и не участвует в генерации (но сохраняется в корзине), ошибки сети/5xx/битый документ не трогают локальные данные и не шумят в консоль, без токена и при выключенном тумблере запросов нет, настройки уезжают сами, но применяются только после подтверждения. |
| `regress` | Все 6 вкладок рендерятся, генерация по каждой категории, воронка заголовков, пакет по регионам, «Ещё варианты» (уникальность id — Bug #11), перегенерация, сканер, инфографика, распознавание по фото. |

Правило Сканера «аккаунт» с этапа 4 ловит и косвенные падежи (`аккаунтом`,
`аккаунта`, `учётной записи`, `профилю`) — раньше срабатывал только именительный.
У «профиля» окончания перечислены поимённо, чтобы не ловить «профилактику» и
«профильную трубу»; на это есть отдельный тест в секции `phys`.

Базовая версия для паритета берётся из `git HEAD` и кладётся в `tests/.baseline/`
(в `.gitignore`). Если правка сознательно меняет промпт — паритет упадёт, и это
повод осознанно обновить ожидания, а не «поправить тест».

**Как менять промпт осознанно.** В `parity.mjs` есть `EXPECTED_SYS_LINES` и
`EXPECTED_SCAN_LABELS` — явный список того, что мы решили изменить. Строки
оттуда вычитаются из новой версии перед сравнением, всё остальное обязано
совпадать байт-в-байт. **Baseline едет вперёд с каждым коммитом**, поэтому
сразу после коммита изменения эти списки нужно очистить: иначе стенд станет
вычитать строку, которая уже есть и в эталоне. Само поведение закрепляется
обычным тестом в своей секции, а не этим списком.

## Разбор журнала — `tools/journal-report.mjs`

Не часть стенда, но живёт рядом и нужен для месячного разбора журнала
самообучения:

```bash
node tools/journal-report.mjs            # всё *.jsonl из ./journal/
node tools/journal-report.mjs файл.jsonl # или конкретные файлы/папки
```

Читает и серверные месячные файлы (`~/avito-journal/YYYY-MM.jsonl` с VPS), и
локальные выгрузки буфера («⬇ Буфер (JSONL)» в ⚙ Настройках) — формат один.
Печатает 10 секций: целостность доставки (дыры по дням, устройства, дубли,
потери), таксономия событий с явным списком ни разу не встретившихся, воронка
цепочек от генерации до размещения, победный индекс варианта, светофор в момент
копии, `editShare`, качество распознавания по парам «предложено → выбрано»,
раскладки обложек, перепись живых и мёртвых функций, ошибки по стадиям.

Две ловушки, заложенные в код:
- **дедуп обязателен** — по `eid`, а у событий старше 09.09.2026 ключа нет, для
  них остаётся грубый `ts + device + event`;
- **`editShare` считается только по доносам с `descPasted: true`** — если поле
  описания в диалоге осталось пустым, клиент подставляет исходный текст сам, и
  доля правок выходит нулевой по построению, а не по факту.

## Почему стенд в репозитории

Набор писался заново трижды (июль — 101 проверка, сентябрь — 93, этап 1 движка
категорий — 129) и каждый раз умирал вместе с временной папкой сессии. Этапы 3–5
направления «категории-конструктор» опираются на тот же паритет, поэтому стенд
переехал в репозиторий. Ключей и данных продавца в нём нет.
