# Аудит avito-helper

Цель — найти то, что теряет работу продавца, искажает его запрос к AI, ломает антидубль или молча не работает. Это не код-ревью стиля, а аудит инструмента глазами единственного пользователя.

## Контекст системы (фиксированные факты)

- **Один HTML-файл** `avito-helper.html` в корне репозитория (~5000+ строк), vanilla JS без сборки и фреймворков. Открывается локально в браузере. Все тексты и комментарии — на русском.
- **Пользователь один** — Денис, продавец Авито (60+ объявлений подписок + 50–150 игр). Цель инструмента: быстро готовить десятки УНИКАЛЬНЫХ объявлений (название ≤50 символов + описание + обложка) для разных регионов, не попадая под бан Авито за дубли и запрещёнку.
- **Модули внутри файла** (порядок примерный, строки плывут — искать по именам):
  - Константы + системный промпт `SYS` (правила названий/описаний/запретов);
  - `callAI` — прокси `https://api.poigraem.shop/api/claude` и `/api/openrouter`, `Authorization: Bearer` из `getProxyToken()` (localStorage `avito_admin_token`), `temperature`, `webSearch` для предзаказов;
  - Генератор: `doGenerate` (прямой путь), воронка `doGenTitlesOnly` → `titleStepHTML` → `doGenDescriptionsForTitles` (основной путь: 8–12 заголовков → выбор → описания, выбранное название хардится по индексу), `doBatchGenerate` (пакет по регионам, чанками по 4), `doRegen`, `doGenAltTitles` (↻×5), `doRephrase`;
  - Промпт-сборка: `buildMsg` / `buildTitlesMsg` / `catInfoBlock` / `buildGamesLists` (ядро vs маскировка) / `fewShotBlock` (избранное той же `_category`) / `styleLabel`;
  - Избранное (`state.favorites`, стабильный `_fid`), очередь (`state.postQueue`, снимки формы `item.form`) и сессия постинга (`doStartSession`, `renderSession`);
  - Модуль обложек `cv*`: режимы «Коллаж» и «Игра», 25+ раскладок (`COLLAGE_LAYOUTS`/`cvCells`), canvas-рисование (`cvDrawCollage`/`cvDrawGame`), маскирующий стикер, текст-оверлей, эффекты, платформ-бейджи, загрузка обложек из IGDB/PS Store через прокси, «4 варианта», скачивание JPEG 1080×1350;
  - История (`state.db`, вкладка «🗂 История») — пул для детектора дублей `dupCheck`;
  - Сканер (`checkAds`, `SCAN_ERRORS`/`SCAN_WARNINGS`) — проверка на запрещёнку Авито;
  - **Event delegation**: ВСЯ интерактивность — один `click`-listener на `document` через `e.target.closest('[data-act]')` + отдельный `cvEl`-селектор для `data-cv-*`; плюс делегированные `change`/`input`.
- **Состояние**: объект `state` + localStorage через `ls()`/`save()`. ВАЖНО: `save()` пишет только явный список ключей — не всё состояние персистится, это постоянный источник потери работы.
- **Правила Авито** (эталон — CLAUDE.md проекта, разделы «Правила и ограничения Авито» и «Оси вариации»): название строго ≤50 символов; запрещены ссылки/контакты/намёки на аккаунты; для игр обязательно «оформляется в цифре» и запрещена цена в названии/описании; дубли детектятся по фото+названию+тексту.
- **Конвенции проекта**: находки нумеруются сериями — GFX-N (графика), UX-N (воронка), F-N (Fable-аудиты, сквозная серия — ПРОДОЛЖАТЬ её, не начинать заново), баги Bug #N. Закрытые находки переезжают в `AUDITS-ARCHIVE.md`. **Закрытие требует визуальной приёмки Денисом** — «код готов» ≠ закрыто. Известный фон: дрейф VPS↔репо (эндпоинты в клиенте могут не существовать на сервере) и параллельные сессии Claude Code в одном репо (проверять `git status` до правок).

## Категории проверки

Прогонять каждую ревизию через три персоны и сквозные критерии.

**Персоны:**
1. **Продавец в спешке** — между ответами клиентам в чате Авито нужно быстро сгенерировать и запостить объявление. Сколько кликов, что можно пропустить не заметив (запрещёнка, неверный товар, обрезанное название)?
2. **Продавец после перерыва** — вернулся через неделю. Понятно ли, что на экране: чей это результат, какого товара, какой давности? Что сбросилось при закрытии вкладки?
3. **Момент ошибки** — нажал не то. Что необратимо? Где нет confirm/undo? Что затирается молча?

**Сквозные критерии:**
1. **Сохранность работы** — каждый кусок state, стоивший токенов или ручного труда (результаты, пакет, заголовки шага 1, настройки обложек, снимки форм), должен переживать F5. Токены = деньги.
2. **Точность запроса к AI** — всё, что продавец ввёл в форму (включая «Доп. указания», стиль, предзаказ/webSearch), должно доходить до КАЖДОГО пути генерации, а не только до основного.
3. **Снимок vs живая форма** — любое действие над ранее сгенерированным вариантом (перегенерация, ↻×5, «Размещено», Сканер, Экспорт) обязано использовать форму/штампы момента генерации (`state.resultsForm`, `_product`, `_category`), а не текущую форму.
4. **Обратимость** — деструктив (очистка очереди/пакета/избранного, импорт с заменой, удаление) — с подтверждением или undo.
5. **Промпт ↔ сканер** — каждый запрет из `SYS` должен ловиться `checkAds`; рассинхрон = «🎉 Всё чисто» на тексте, который забанят.
6. **Антидубль** — и тексты (структурная вариативность, исключение уже размещённых), и картинки («варианты» обложек должны реально отличаться: зеркало/кадр/тон/стикер, не только фон).
7. **Достижимость контролов** — каждая кнопка реально обрабатывается (ветка в делегированном switch / `cvEl`-селекторе), ничто не глушится `stopPropagation`, раскладки/фичи доступны из UI.
8. **Симметрия режимов** — то, что есть в одном режиме (коллаж/игра, список/конвейер/пакет), не должно беспричинно отсутствовать в другом (скачивание, ★, лимиты, счётчики).
9. **Мобильное использование** — touch-аналоги mouse-событий канваса, порядок колонок на узком экране, автоскролл к результатам.
10. **Связность воронки** — переходы между вкладками переносят данные (карточка → сканер, карточка → поиск обложки, пакет → очередь), а не заставляют копировать руками.

## Как выявлять

1. **Читать весь файл сплошняком** порциями по ~700 строк (Read с offset/limit). Не выборочно — половина находок живёт на стыках модулей.
2. **Сначала переоценить всё старое**: открыть CLAUDE.md проекта, взять все открытые находки (GFX/UX/F/Bug) и проверить каждую по живому коду. Строки в ссылках устаревают — фиксировать актуальные. Итог по каждой: подтверждена / предлагаю закрыть (с обоснованием) / смягчена.
3. **Для каждой AI-функции** проследить полную цепочку: какие поля формы попадают в промпт (notes? style? few-shot? excludeTitles?), какие opts уходят в `callAI` (webSearch? max_tokens хватит на N вариантов? temperature?), из какой формы строится запрос (живая vs снимок), штампуются ли `_product`/`_category` на результат и переживают ли штампы замену варианта.
4. **Для каждого поля state** ответить: есть ли в `save()` И в init через `ls()`? Если нет — что теряется при F5 и сколько это стоило?
5. **Для каждой кнопки** найти обработчик: `data-act` → ветка switch, `data-cv-*` → `cvEl`-селектор (атрибут должен быть В селекторе `closest`, иначе кнопка мертва). Искать `stopPropagation` — в этой архитектуре он почти всегда баг.
6. **Для canvas-фич**: у mouse-события есть touch-аналог? фича попадает в скачиваемый файл? «4 варианта» уважают ручные настройки или перетирают их пресетами? хитбоксы соответствуют реальной форме элемента?
7. **Сверить `SYS` ↔ `SCAN_ERRORS`/`checkAds`** построчно: список запрещённых слов/паттернов промпта против регэкспов сканера.
8. **Сверить клиент ↔ VPS**: каждый URL в fetch — существует ли эндпоинт на живом сервере (спросить Дениса или проверить, если есть доступ); UI не должен предлагать провайдера/фичу, которая гарантированно даст 404.
9. Код при аудите **НЕ править** — только диагноз. Правки — отдельным решением Дениса после отчёта.

## Типичные зоны риска в этой системе

- **Делегирование vs локальные слушатели**: `stopPropagation` на обёртке глушит все кнопки внутри (прецедент F1); локальные listeners теряются при перерисовке innerHTML.
- **Непersистентный state**: новые куски состояния (`batchResults`, `titleStep`, `resultsForm`, объект `cv`) регулярно забывают добавить в `save()` — потеря токенов/настроек при F5 (прецеденты GFX-10, F10, F12).
- **Живая форма вместо снимка**: каждый НОВЫЙ обработчик над старыми результатами рискует прочитать `state.form` вместо `state.resultsForm`/штампов (прецеденты F4, F12).
- **Новый путь генерации забывает поля старого**: при добавлении воронки/режима теряются notes, few-shot, webSearch, excludeTitles, которые основной путь передаёт (прецедент F9).
- **Асимметрия режимов коллаж/игра**: кнопки, лимиты (10 фото), секции и скачивание добавляются в один режим и забываются в другом (прецеденты F11, F18).
- **max_tokens vs объём ответа**: фиксированный бюджет + переменное число вариантов/веб-поиск = обрезанный JSON (прецеденты F2, F5). Проверять каждый `callAI` с нестандартным max_tokens.
- **Проза вокруг JSON**: любой новый парс ответа модели обязан идти через `extractJSON`, не через голый `JSON.parse` (прецедент F3).
- **Рассинхрон промпт↔сканер**: запреты добавляют в `SYS`, а регэкспы сканера не обновляют (прецедент F19); пороги/лимиты дублируются в нескольких местах и разъезжаются (прецедент F7).
- **Mouse-only canvas и мобильная раскладка**: drag/wheel без touch-аналогов, превью внизу на узком экране, нет автоскролла (GFX-8, GFX-9, UX-11).
- **Google Fonts из РФ**: и UI, и canvas-текст молча падают в системный шрифт (GFX-13, UX-12) — учитывать при любых новых текстах на канвасе.
- **Дрейф VPS↔репо**: эндпоинт «числится задеплоенным» ≠ существует (прецедент Bug #9).
- **Параллельные сессии в одном репо**: перед правками — `git status`; коммитить только явные пути своих файлов; чужие изменённые файлы не трогать.

## Формат вывода

**Каждая находка:**
- Номер: продолжить сквозную F-серию (посмотреть в CLAUDE.md последний использованный F-номер);
- Серьёзность: 🔴 (теряется работа/деньги, искажается запрос, неверный товар) / 🟠 (риск ошибки или потери, нет пути восстановления) / 🟡 (полировка, мелкий рассинхрон);
- Место: имя функции/обработчика + примерные строки на момент аудита;
- Что происходит: механика бага одним-двумя предложениями;
- Сценарий «глазами Дениса»: конкретная последовательность действий, при которой это выстрелит;
- Рекомендация: конкретная правка («добавить X в save()», «пробросить notes в buildTitlesMsg»), не абстракция.

**Структура отчёта:**
1. Что работает хорошо (не трогать) — коротко.
2. Переоценка старых находок: подтверждена / предлагаю закрыть / смягчена. Закрывать в архив самостоятельно НЕЛЬЗЯ — только предлагать; перенос делает /session-end после визуальной приёмки.
3. Новые находки по серьёзности.
4. Приоритизированный план: инструмент ежедневный — экономия секунд на частой операции важнее красоты редкого экрана; дешёвые фиксы главной воронки — в начало.
5. Отдельно — идеи развития (не баги), привязанные к трём столпам: качество описаний, качество обложек, полнота проверок.

**Куда класть результат:** полный отчёт в чат + раздел `## Расширенный аудит Fable №K — <дата>` в CLAUDE.md проекта (перед разделом предыдущего аудита), с переоценкой старого, новыми находками и планом. Спросить Дениса о порядке реализации — не начинать фиксы без его выбора.
