# Задание серверной сессии: два референса в `/api/image` (серия фото 2б)

Составлено 28.09.2026 на Windows-стороне. Выполнять на VPS в `~/poigraem-backend`
(⚠️ сначала `git pull`). Итог записать в `CLAUDE-VPS.md` и ответить Денису одной строкой:
«пропускает / режет / правка нужна».

## Зачем

В карточке «Товар в интерьере» появилась серия: до 5 фото товара с разных сторон → по кадру
на каждое, в одной комнате. Кадры 2…5 уходят с **двумя** референсами:

```json
{
  "prompt": "…",
  "input_references": [
    { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,… (фото ракурса, ≤1568 px)" } },
    { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,… (первый кадр серии, ≤1024 px)" } }
  ],
  "aspect_ratio": "3:4",
  "quality": "medium"
}
```

Тело — до ~1 МБ (клиент сам не отправляет больше 3.5 МБ и ужимает первый кадр в JPEG).

## Что проверить (только чтение, без правок и без платных запросов)

1. Белый список параметров `/api/image`: проходит ли `input_references` **массивом целиком**,
   или маршрут берёт только `[0]` / режет длину / перекладывает в одиночное поле.
2. Лимит тела `OPENROUTER_IMAGE_BODY_LIMIT` — всё ещё 4 МБ?
3. Нет ли проверки «ровно один референс» в валидации.

## Если режет

Правку не делать без слова Дениса: описать в `CLAUDE-VPS.md`, где режет и какая правка
нужна (ожидаемо — пропустить массив до 2 элементов с проверкой формы каждого). Клиент при
этом не ломается: кадр уйдёт с одним референсом, просто комнаты в серии будут разными.

## Живая проба (по слову Дениса, стоит ~$0.05)

После проверки кода — одна серия из 2 кадров черновиком с боевой ссылки: совпадает ли
комната на втором кадре с первым и не перетащила ли модель товар с первого кадра.
